

\chapter{Modelo C4 de Arquitectura}

El modelo C4 (Context, Containers, Components, Code) propuesto por Simon Brown ofrece una manera abstracta de comunicar la arquitectura de un sistema de software a distintos niveles de detalle. Este capítulo presenta los tres primeros niveles para el sistema FisioManager.

El diagrama de contexto muestra a FisioManager como una caja azul y describe sus interacciones con usuarios y sistemas externos.

\subsection{Actores y sistemas externos}

\begin{itemize}
  \item \actor{Paciente:} interactúa con FisioManager vía web responsiva para visualizar rutinas, ejecutar ejercicios y registrar feedback por voz.
  \item \actor{Terapeuta:} gestiona pacientes, crea rutinas, asigna y supervisa progreso.
  \item \actor{Administrador:} actor único que supervisa indicadores agregados de uso y desempeño de la clínica y, a la vez, gestiona usuarios, accesos y monitoreo técnico de la plataforma.
  \item \actor{Servicio de IA (STT + LLM):} transcribe audio y analiza sentimientos.
  \item \actor{ElevenLabs (TTS):} genera audio de respuesta cuando aplique.
  \item \actor{Almacenamiento de Objetos (MinIO/S3):} persiste audios y videos.
  \item \actor{Proveedor de Email (SMTP/SendGrid):} envía notificaciones por correo.
  \item \actor{Notificaciones Push (FCM):} envía recordatorios a dispositivos móviles.
\end{itemize}

\subsection{Componentes del Servicio de Feedback}

\begin{itemize}
  \item \textbf{FeedbackController:} expone los endpoints REST públicos para registro y consulta de feedback.
  \item \textbf{SesionController:} expone los endpoints de inicio, marcado de ejercicios y finalización de sesión.
  \item \textbf{FeedbackApplicationService:} implementa el caso de uso de registro de feedback orquestando almacenamiento de audio, persistencia, publicación de eventos y solicitud de análisis.
  \item \textbf{SesionApplicationService:} gestiona el ciclo de vida de las sesiones de ejecución.
  \item \textbf{AudioStorageService:} encapsula la subida y descarga de audio sobre MinIO/S3, aplicando compresión y conversión de formato cuando aplique.
  \item \textbf{AnalisisIAClient:} cliente HTTP tipado hacia el Servicio de IA, con políticas de reintento exponencial y circuit breaker.
  \item \textbf{EventPublisher:} publica eventos de dominio (FeedbackRegistrado, AlertaDolorAlto) sobre RabbitMQ.
  \item \textbf{FeedbackRepository / SesionRepository:} abstraen el acceso a datos sobre Entity Framework Core.
  \item \textbf{FeedbackValidator:} valida los datos recibidos (rango de dolor, formato y tamaño de audio, longitud de transcripción) usando FluentValidation.
  \item \textbf{FeedbackMapper:} convierte entre DTOs públicos y entidades de dominio mediante AutoMapper.
\end{itemize}
